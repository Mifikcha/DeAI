# DeAI

DeAI — небольшая языковая модель на PyTorch с распределённым обучением по методу DiLoCo. В комплекте есть веса модели на 120 576 параметров, обученной с нуля на коротких русскоязычных наблюдениях о природе. Ей можно дать начало фразы и получить продолжение в стиле этого корпуса.

Архитектура DeAI — авторегрессионный Transformer с причинным вниманием. DiLoCo определяет, как его копии совместно обновляют веса во время обучения. Для генерации достаточно одной копии модели на CPU. Веса в репозитории относятся к двухслойной демонстрационной модели. В разделе о масштабировании приведены параметры для отдельного эксперимента на 86 млн параметров.

## Как работает модель

Модель читает текст как последовательность байтов UTF-8. Два слоя Transformer обрабатывают последние 64 байта. Маска внимания позволяет каждой позиции видеть только себя и предыдущие позиции. При обучении модель предсказывает следующий байт, а при генерации добавляет выбранный байт к контексту и повторяет шаг. Один символ кириллицы обычно занимает два байта. [Реализация модели](model.py)

**Вход и выход.** Словарь фиксирован и содержит все 256 значений байта. Идентификатор токена равен значению байта от 0 до 255. Пробелы и переводы строк кодируются тем же способом. У модели нет специальных токенов начала, конца или заполнения. При размере батча `B` и длине окна `T` вход имеет форму `[B, T]` и тип `torch.long`. Выход — логиты формы `[B, T, 256]`. Логиты позиции `i` задают распределение для байта `i + 1` после применения softmax.

**Прямой проход в конфигурации готовых весов.**

1. Суммируются обучаемое представление байта и обучаемое представление позиции внутри окна. Размерность обоих векторов — 64.
2. В каждом из двух блоков сначала применяется LayerNorm, затем общая линейная проекция `64 → 192` строит запросы, ключи и значения (Q, K, V). Причинное внимание PyTorch (`is_causal=True`) использует 4 головы по 16 координат. Их выходы объединяются, проходят через проекцию `64 → 64` и складываются со входом блока.
3. Вторая LayerNorm и сеть `64 → 256 → GELU → 64` образуют вторую ветвь блока. Её результат также прибавляется ко входу этой ветви. После последнего блока применяется финальная LayerNorm. Выходная проекция использует ту же матрицу, что и входные представления байтов (weight tying), без отдельного смещения.

На представления байтов приходится 16 384 параметра, на представления позиций — 4 096, на каждый из двух блоков — 49 984, на финальную LayerNorm — 128. Обучение и сохранённые веса используют FP32. Веса линейных слоёв и представлений инициализируются из нормального распределения со средним 0 и стандартным отклонением 0,02. Смещения линейных слоёв изначально нулевые. Dropout равен 0.

## Как работает DiLoCo

DiLoCo (*Distributed Low-Communication*) задаёт способ совместного обучения нескольких копий модели. Один раунд устроен так.

1. Все процессы начинают с одинаковых весов. Каждый выполняет `H` локальных шагов AdamW на своей части корпуса.
2. Каждый процесс вычисляет разность между начальными весами раунда и своими весами после обучения. Процессы усредняют эти разности одной операцией `all_reduce`.
3. Полученная разность служит псевдоградиентом. Внешний оптимизатор SGD с импульсом Нестерова обновляет общие веса. Каждый процесс начинает с них следующий раунд и сохраняет свою историю AdamW.

Обмен весовыми обновлениями происходит раз в `H` шагов. Увеличение `H` уменьшает частоту обмена, но за это время локальные копии могут сильнее разойтись. Между раундами быстрый участник ждёт остальных. [Алгоритм 1 в статье Google DeepMind](https://arxiv.org/html/2311.08105) · [Реализация DiLoCo в DeAI](diloco.py)

Пусть `W` — число процессов, `θ` — общие веса в начале раунда, `θᵣ` — локальные веса процесса `r` после `H` шагов. Импульс `v` изначально равен нулю. При внешней скорости обучения `η` и коэффициенте импульса `μ` каждый процесс обновляет веса по одной формуле.

```text
g = sum(θ - θᵣ для всех r) / W
v = μ * v + g
θ = θ - η * (g + μ * v)
```

До первого раунда процесс с номером 0 (`rank 0`) рассылает начальные веса через `broadcast`. Для каждого раунда все разности упаковываются в один плоский FP32-вектор. В конфигурации на 120 576 параметров размер такого вектора равен 471 КиБ. Одна операция `all_reduce(SUM)` и деление на `W` дают всем участникам одинаковое среднее. Каждый применяет внешний оптимизатор к своей копии общих весов и копирует результат обратно в модель. Состояния AdamW остаются локальными между раундами. При `W=1` оба оптимизатора продолжают работать, вызовы сетевых операций пропускаются.

## Обучить на своём тексте

Эта команда воспроизводит демонстрационное обучение на двух процессах CPU. Чтобы использовать свой корпус, замените путь после `--data` на текстовый файл в UTF-8.

```bash
torchrun --standalone --nproc-per-node=2 train.py --device cpu \
  --data data/observations.txt --rounds 120 --local-steps 20 --output runs/demo.pt
python generate.py --checkpoint runs/demo.pt --prompt "Вечером " --temperature 0.7
```

### Корпус, выборка и целевая функция

Файл читается как массив `uint8` через `torch.from_file`. Для файла размером `N` байтов граница проверки равна `S = floor(9N/10)`. Байты от `0` до `S` (правая граница исключена) делятся на последовательные непересекающиеся части между процессами. Интервал `[S, N)` целиком отводится под проверку. Разбиение идёт по байтовым смещениям и может пройти внутри строки или многобайтового символа. Каждая обучающая часть и проверочная часть должны содержать хотя бы `context + 1` байт.

В демонстрационном файле 36 строк и 5 099 байт. При двух процессах первый получает 2 294 байта для обучения, второй — 2 295, для проверки остаётся 510 байт. На каждом шаге процесс равновероятно выбирает с возвращением начала окон внутри своей части. Для контекста длины `T` одно окно содержит `T + 1` байт. Первые `T` служат входом, последние `T` — целями, сдвинутыми на одну позицию. Минимизируется средняя кросс-энтропия по всем `B × T` целевым байтам. [Демонстрационный текст](data/observations.txt) · [Подготовка данных и цикл обучения](train.py)

### Параметры демонстрационного обучения

- `--rounds 120 --local-steps 20 --batch-size 8`. Это 2 400 шагов AdamW на каждом процессе, 120 общих обновлений и 2 457 600 предсказаний целевого байта суммарно на двух процессах. В это число входят повторные выборки тех же фрагментов.
- `--inner-lr 0.001`. AdamW использует `betas=(0.9, 0.999)`, `eps=1e-8` и `weight_decay=0.01` для всех обучаемых параметров. Скорость обучения постоянна. На каждый батч приходится одно обновление.
- `--outer-lr 0.7 --momentum 0.9`. Внешний SGD использует `nesterov=True`, `dampening=0` и `weight_decay=0`.
- `--seed 42` задаёт инициализацию модели. Для обучающих окон процесс использует отдельный генератор с зерном `seed + rank`. Глубина, ширина, число голов и контекст по умолчанию совпадают с конфигурацией готовых весов.

**Как читать метрики.** `train_loss_rank0` — средняя кросс-энтропия локальных батчей только процесса 0 за текущий раунд. `initial_val_loss` вычисляется до обучения, `val_loss` — по общим весам после каждой синхронизации. Для проверки процесс 0 каждый раз заново устанавливает зерно `31415` и выбирает одни и те же 4 батча по 4 окна из отложенной части. Значения указаны в натуральных логарифмических единицах на байт. В демонстрационном запуске ошибка на этих окнах снизилась с **5,5615 до 0,3089**. Корпус содержит повторяющиеся фразы. Результат показывает, насколько модель освоила этот узкий стиль. Генерацию на других темах и качество диалога отдельно не оценивали.

### Масштабирование и запуск на нескольких машинах

Для одного процесса используйте `python train.py`. Для двух GPU используйте ту же команду `torchrun` с `--device cuda`. Каждый GPU хранит полную копию модели и состояния оптимизаторов. Для эксперимента на большом корпусе параметры `--layers 12 --width 768 --heads 12 --context 1024` задают Transformer на 86 039 040 параметров с контекстом 1024 байта. Такой запуск обучает новую модель с нуля.

Все размеры должны быть положительными, а `width` — делиться на `heads`. Для окна в 1 024 байта нужен более длинный корпус, поскольку проверочная часть демонстрационного файла содержит только 510 байт. Состав участников фиксируется при запуске. На CPU обмен идёт через Gloo, на NVIDIA GPU — через NCCL. В режиме `--device auto` выбирается CUDA при её доступности, иначе CPU. `torchrun` задаёт `WORLD_SIZE` и `RANK` для всей группы, а `LOCAL_RANK` определяет индекс GPU на конкретной машине. На CPU число потоков на процесс берётся из `OMP_NUM_THREADS` и по умолчанию равно 1. Обучение и генерация в этом проекте проверены на CPU.

Для двух машин с одним GPU на каждой положите одинаковый корпус на обе машины. Выполните команду ниже на каждой, подставив адрес первой машины и значение `NODE_RANK` — 0 на первой и 1 на второй. Обеим машинам нужно сетевое соединение друг с другом. Итоговые веса запишет первая машина. [Руководство по torchrun](https://docs.pytorch.org/docs/stable/elastic/run.html)

```bash
torchrun --nnodes=2 --nproc-per-node=1 --node-rank="$NODE_RANK" \
  --master-addr="$MASTER_ADDR" --master-port=29500 \
  train.py --device cuda --data data/observations.txt --output runs/two-hosts.pt
```

## Сохранённые веса и генерация

Процесс 0 сохраняет итоговые веса после последнего раунда. Он пишет во временный файл в том же каталоге и атомарно заменяет им целевой файл после успешной сериализации. По умолчанию `train.py` пишет в `runs/demo.pt`, а `generate.py` читает поставляемый `checkpoints/observations.pt`. Для генерации со своими весами передайте путь через `--checkpoint`.

Файл `.pt` — словарь PyTorch с тремя ключами.

- `config` — параметры конструктора `ModelConfig`. В готовом файле это `{"context": 64, "layers": 2, "heads": 4, "width": 64}`.
- `model` — именованные тензоры `LanguageModel.state_dict()`. Генератор создаёт модель из `config` и загружает в неё эти тензоры.
- `rounds` — число завершённых внешних раундов, в готовом файле `120`. Файл предназначен для инференса. Состояния AdamW, импульс внешнего SGD и позиции генераторов случайных чисел в него не входят. Новый запуск `train.py` начинает обучение с нуля.

Генератор читает файл с `weights_only=True` на CPU и работает в режиме `eval()` с отключённым вычислением градиентов. `--prompt` принимает непустую строку. На каждом шаге модель заново обрабатывает последние `context` байтов, нумеруя позиции от нуля. Для выбора байта используются только логиты последней позиции. При `--temperature 0` берётся `argmax`, при положительной температуре выполняется случайная выборка из `softmax(logits / temperature)`. Значения по умолчанию — `--temperature 0.7 --seed 42 --max-new-bytes 120`. Генерация завершается по исчерпании бюджета байтов. Вывод содержит исходную строку и продолжение. Незавершённый в конце символ UTF-8 опускается, некорректные последовательности внутри строки отображаются как `�`. [Генератор](generate.py)
